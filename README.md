# fit-viewer

A small learning project for **CMake**, **Conan 2**, **GoogleTest** and **Qt 6**:
a from-scratch decoder for Garmin `.FIT` activity files (as written by a
Forerunner 35), a Qt Widgets viewer and a command-line dump tool.

```
fit-viewer/
├── CMakeLists.txt           top level: options, subdirectories
├── conanfile.py             dependencies (gtest) + CMake integration
├── cmake/CompilerWarnings.cmake
├── libs/fit/                core library, no Qt dependency
│   ├── include/fit/         public headers (crc, types, decoder, activity, format)
│   └── src/
├── tools/fitdump/           CLI: summary or raw dump of a .fit file
├── app/                     Qt 6 Widgets viewer (model/view)
├── tests/                   GoogleTest suite + FitBuilder test helper
└── .github/workflows/ci.yml
```

The core library knows nothing about Qt, so everything that can be tested
(decoding, unit conversion, formatting) is tested without a GUI. The Qt app is
a thin layer on top.

## Prerequisites

- C++20 compiler with `std::format` + chrono formatting: GCC 13+, Clang 17+ (libc++), or MSVC 2022
- CMake 3.23+ and Ninja (optional but recommended)
- Conan 2: `pip install conan`
- Qt 6.4+ from your system (`apt install qt6-base-dev`, `brew install qt`, or the Qt online installer)

## Build with Conan

```bash
conan profile detect                  # once: detects your compiler into ~/.conan2/profiles/default
conan install . --build=missing       # fetches/builds gtest, writes build/Release/generators/
cmake --preset conan-release          # preset generated by conan (CMakeUserPresets.json)
cmake --build --preset conan-release
ctest --preset conan-release --output-on-failure
```

Variations:

```bash
conan install . --build=missing -s build_type=Debug    # then use the conan-debug preset
conan install . --build=missing -o with_gui=False      # skip the Qt app (e.g. headless CI)
cmake --preset conan-release -DCMAKE_PREFIX_PATH=$HOME/Qt/6.8.0/gcc_64   # Qt not found
conan build .                                          # install + configure + build + test in one go
```

Without Conan (using a system-installed GoogleTest) plain CMake also works,
because the CMake files only use `find_package()`:

```bash
cmake -S . -B build/sys -G Ninja && cmake --build build/sys && ctest --test-dir build/sys
```

## Running

The Forerunner 35 shows up as a USB mass-storage drive called `GARMIN`;
activities are in `GARMIN/ACTIVITY/*.FIT`.

```bash
./build/Release/app/fitviewer /media/$USER/GARMIN      # or open it from File → Open watch folder
./build/Release/tools/fitdump/fitdump some.fit         # summary
./build/Release/tools/fitdump/fitdump some.fit --raw   # every message, raw field values
```

Copy files off the watch before experimenting; the viewer only reads, but
it's a good habit.

## How the pieces fit together

**Conan** resolves dependencies and generates CMake glue. `conanfile.py` declares
`gtest` as a `test_requires`. On `conan install`:
- `CMakeDeps` writes `GTestConfig.cmake` into `build/<type>/generators/`, so
  `find_package(GTest)` in `tests/CMakeLists.txt` finds Conan's copy;
- `CMakeToolchain` writes `conan_toolchain.cmake` (compiler, build type, paths)
  and a `CMakePresets.json`, referenced from `CMakeUserPresets.json` in the repo
  root (git-ignored; it's machine-specific).

The CMake files never mention Conan; that's the point. Conan is one way to
satisfy `find_package`, the system is another.

**CMake** is written target-first: `fit` is a library with `PUBLIC` headers
(via `FILE_SET HEADERS`) and a `PUBLIC` C++20 requirement, so linking
`fitviewer::fit` is all a consumer needs. Warnings are `PRIVATE` per target.
The `::` alias makes a misspelled target a configure error rather than a
mysterious link flag.

**GoogleTest**: plain `TEST`s for the decoder rules, a fixture (`TEST_F`) for
the activity conversion, and `gtest_discover_tests` so each test is a separate
`ctest` entry (`ctest -R Decoder`). `tests/fit_builder.hpp` assembles FIT files
byte by byte, so each format rule (endianness, compressed timestamps,
developer fields, CRC, truncation) gets a focused test without binary fixtures.

**FIT in brief**: a 12/14-byte header, then records, then a CRC-16. Each record
is either a *definition* (maps a local type 0–15 to a global message number
and a field layout) or a *data* message that uses a previously defined local
type. Compressed-timestamp headers store only the low 5 bits of the time.
Values are integers with a scale/offset (e.g. altitude = raw/5 − 500 m),
positions are in "semicircles" (2³¹ = 180°), and time counts from 1989-12-31.
The full spec and profile are in Garmin's FIT SDK.

## Exercises to extend it

1. Plot heart rate and pace with **QtCharts** (add the component to `find_package`).
2. Decode **lap** messages (global 19) and show splits; test-drive it with `FitBuilder`.
3. Replace repetitive tests with **parameterised tests** (`TEST_P`) over all base types.
4. Add an **ASan/UBSan** build via a `CMakePresets.json` of your own, and a **libFuzzer** target for `fit::decode`.
5. Export **GPX**, then turn `libs/fit` into a real Conan package: `package()` / `package_info()` plus a `test_package/`, and `conan create .`.
6. Add `install()` rules and **CPack** to produce a `.deb` or `.zip`.
